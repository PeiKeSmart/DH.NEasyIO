## 1. 功能概述

### 1.1 什么是签名URL

签名URL是一种临时的、带有安全签名的文件访问地址，类似于七牛云、阿里云OSS、腾讯云COS的私有资源访问方案。

```
普通私有文件访问：
https://api.example.com/api/v1/io/12345
❌ 问题：需要在请求头携带认证信息，前端无法直接用于 img/video 标签

签名URL访问：
https://api.example.com/api/v1/io/signed/12345?expires=1738329600&sign=abc123...
✅ 优势：可以直接用于 img/video 标签，无需额外请求头
```

### 1.2 核心特性

- ✅ **前端直接使用**：签名URL可直接用于 `<img>`、`<video>`、`<a>` 等标签
- ✅ **临时有效**：默认1小时过期，最长7天，防止滥用
- ✅ **批量生成**：支持一次请求生成多个文件的签名URL
- ✅ **安全可靠**：使用 HMAC-SHA256 签名，与系统API认证一致
- ✅ **项目隔离**：仅项目成员可访问，自动验证项目权限

### 1.3 适用场景

| 场景 | 是否适合 | 说明 |
|------|---------|------|
| 图片列表预览 | ✅ 强烈推荐 | 一次生成所有图片的签名URL，前端直接渲染 |
| 视频播放 | ✅ 推荐 | 生成长效签名URL（1-24小时），支持完整播放 |
| 文件下载 | ✅ 推荐 | 生成临时下载链接，用户点击直接下载 |
| 高敏感文件 | ⚠️ 谨慎使用 | 建议通过业务后端代理，不暴露签名URL |
| 用户级权限控制 | ❌ 不适合 | 签名URL仅验证项目级权限，用户级权限需在业务层实现 |

## 2. 业务场景

### 2.1 场景一：项目文件列表（图片预览）

**需求**：项目管理页面需要显示项目的所有附件图片缩略图。

**问题**：
- 项目设置了 AccessLevel=2（私有），普通URL无法直接访问
- 每张图片都单独请求后端会导致大量HTTP请求
- 无法使用浏览器缓存，性能差

**解决方案**：使用批量签名URL

```
前端 ───> 业务后端：请求项目文件列表（1次请求）
业务后端 ───> EasyIO：批量生成签名URL（1次请求）
业务后端 ───> 前端：返回文件信息+签名URL
前端 ───> EasyIO：直接加载所有图片（浏览器并行，可缓存）
```

### 2.2 场景二：视频播放

**需求**：播放私有项目的教学视频（30分钟）。

**问题**：
- 视频播放时间长，需要长期有效的URL
- 传统方式需要持续保持认证状态
- 用户可能暂停、拖动进度条，需要多次请求

**解决方案**：生成长效签名URL（1-2小时）

```
前端 ───> 业务后端：请求视频播放URL
业务后端：验证用户权限
业务后端 ───> EasyIO：生成2小时有效的签名URL
业务后端 ───> 前端：返回签名URL
前端：<video> 标签直接播放，无需额外认证
```

### 2.3 场景三：临时分享链接

**需求**：项目经理需要将一个私有文件临时分享给外部客户。

**解决方案**：生成短期签名URL（5-30分钟）

```csharp
// 业务后端生成临时分享链接
var signedUrl = await GenerateSignedUrlAsync(fileId, expiresInSeconds: 1800); // 30分钟
// 发送给客户：https://api.example.com/api/v1/io/signed/12345?expires=...&sign=...
```

## 3. 实现原理

### 3.1 签名算法

EasyIO使用与系统API认证相同的签名算法，确保一致性：

```
签名数据格式：{fileId}:{projectCode}:{expires}
签名算法：HMAC-SHA256(签名数据, ProjectApiSecret)
```

**示例计算过程**：

```csharp
// 1. 准备签名数据
var fileId = 12345;
var projectCode = "ProjectA";
var expires = 1738329600; // 2026-01-31 12:00:00 UTC
var data = $"{fileId}:{projectCode}:{expires}";
// 结果："12345:ProjectA:1738329600"

// 2. 使用项目密钥计算 HMAC-SHA256
var apiSecret = "your-project-secret";
var signature = ComputeHmacSha256(data, apiSecret);
// 结果："a1b2c3d4e5f6..."

// 3. 构造签名URL
var signedUrl = $"https://api.example.com/api/v1/io/signed/{fileId}?expires={expires}&sign={signature}";
```

### 3.2 验证流程

```
1. 客户端请求：GET /api/v1/io/signed/12345?expires=1738329600&sign=abc123...

2. EasyIO服务端验证：
   ├─ 检查文件是否存在
   ├─ 检查过期时间（expires > 当前时间）
   ├─ 获取文件所属项目的ApiSecret
   ├─ 重新计算签名：HMAC-SHA256("12345:1:1738329600", ApiSecret)
   ├─ 对比签名是否一致
   └─ 验证通过 → 返回文件内容
          验证失败 → 返回 401/403 错误
```

### 3.3 安全保障

- **时效性**：签名URL包含过期时间，超时自动失效
- **不可伪造**：签名使用项目密钥（ApiSecret），外部无法计算
- **项目隔离**：签名绑定项目ID，无法跨项目访问
- **防篡改**：任何参数（fileId、projectCode、expires）被修改后签名验证失败

## 4. 后端实现

### 4.1 EasyIO API端点

#### 端点1：单个文件签名URL访问

```http
GET /api/v1/io/signed/{fileId}?expires={timestamp}&sign={signature}&inline={true|false}
```

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| fileId | Int64 | 是 | 文件ID |
| expires | Int64 | 是 | 过期时间戳（Unix秒） |
| sign | String | 是 | HMAC-SHA256签名 |
| inline | Boolean | 否 | 是否内联显示（true=预览，false=下载） |

**响应**：
- 成功：返回文件流（Content-Type根据文件类型设置）
- 失败：返回JSON错误信息
  ```json
  {
    "code": 401,
    "message": "签名已过期"
  }
  ```

#### 端点2：批量生成签名URL

```http
POST /api/v1/io/signed-urls
Content-Type: application/json

{
  "fileIds": [12345, 12346, 12347],
  "expiresInSeconds": 3600,
  "baseUrl": "https://api.example.com"
}
```

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| fileIds | Int64[] | 是 | 文件ID数组 |
| expiresInSeconds | Int32 | 否 | 有效期（秒），默认3600（1小时），最大604800（7天） |
| baseUrl | String | 否 | API基础URL，默认使用当前请求的Host |

**响应示例**：

```json
{
  "urls": [
    {
      "fileId": 12345,
      "fileName": "image1.jpg",
      "url": "https://api.example.com/api/v1/io/signed/12345?expires=1738333200&sign=abc123...",
      "expiresAt": "2026-01-31T13:00:00Z"
    },
    {
      "fileId": 12346,
      "fileName": "image2.png",
      "url": "https://api.example.com/api/v1/io/signed/12346?expires=1738333200&sign=def456...",
      "expiresAt": "2026-01-31T13:00:00Z"
    }
  ],
  "expiresInSeconds": 3600,
  "generatedAt": "2026-01-31T12:00:00Z"
}
```

**鉴权要求**：需要项目API Key认证（与其他API一致）

```http
POST /api/v1/io/signed-urls
X-Api-Key: your-api-key
X-Project-Code: your-project
X-Timestamp: 1738329600
X-Signature: calculated-hmac-sha256
```

### 4.2 业务后端集成

#### 方式1：直接调用EasyIO（推荐）

```csharp
using System;
using System.Collections.Generic;
using System.Net.Http;
using System.Text;
using System.Text.Json;
using System.Threading.Tasks;

namespace YourApp.Services;

/// <summary>文件服务（集成EasyIO签名URL）</summary>
public class FileService
{
    private readonly HttpClient _httpClient;
    private readonly String _easyIOBaseUrl;
    private readonly String _apiKey;
    private readonly String _projectCode;
    private readonly String _apiSecret;

    public FileService(HttpClient httpClient, IConfiguration configuration)
    {
        _httpClient = httpClient;
        _easyIOBaseUrl = configuration["EasyIO:BaseUrl"];
        _apiKey = configuration["EasyIO:ApiKey"];
        _projectCode = configuration["EasyIO:ProjectCode"];
        _apiSecret = configuration["EasyIO:ApiSecret"];
    }

    /// <summary>批量生成签名URL</summary>
    /// <param name="fileIds">文件ID列表</param>
    /// <param name="expiresInSeconds">有效期（秒），默认3600</param>
    public async Task<List<SignedUrlResult>> GenerateSignedUrlsAsync(
        List<Int64> fileIds, 
        Int32 expiresInSeconds = 3600)
    {
        var timestamp = DateTimeOffset.UtcNow.ToUnixTimeSeconds().ToString();
        var signature = CalculateSignature("POST", "/api/v1/io/signed-urls", timestamp);

        var requestBody = new
        {
            fileIds = fileIds,
            expiresInSeconds = expiresInSeconds,
            baseUrl = _easyIOBaseUrl.Replace("/api/v1/io", "")
        };

        var request = new HttpRequestMessage(HttpMethod.Post, $"{_easyIOBaseUrl}/signed-urls");
        request.Content = new StringContent(
            JsonSerializer.Serialize(requestBody), 
            Encoding.UTF8, 
            "application/json"
        );
        
        request.Headers.Add("X-Api-Key", _apiKey);
        request.Headers.Add("X-Project-Code", _projectCode);
        request.Headers.Add("X-Timestamp", timestamp);
        request.Headers.Add("X-Signature", signature);

        var response = await _httpClient.SendAsync(request);
        response.EnsureSuccessStatusCode();

        var json = await response.Content.ReadAsStringAsync();
        var result = JsonSerializer.Deserialize<SignedUrlsResponse>(json);
        
        return result.Urls;
    }

    /// <summary>计算API签名</summary>
    private String CalculateSignature(String method, String path, String timestamp)
    {
        var signString = $"{method}:{path}:{timestamp}:{_apiKey}";
        using var hmac = new System.Security.Cryptography.HMACSHA256(Encoding.UTF8.GetBytes(_apiSecret));
        var hashBytes = hmac.ComputeHash(Encoding.UTF8.GetBytes(signString));
        return BitConverter.ToString(hashBytes).Replace("-", "").ToLower();
    }
}

/// <summary>签名URL结果</summary>
public class SignedUrlResult
{
    public Int64 FileId { get; set; }
    public String FileName { get; set; }
    public String Url { get; set; }
    public DateTime ExpiresAt { get; set; }
}

/// <summary>批量签名URL响应</summary>
public class SignedUrlsResponse
{
    public List<SignedUrlResult> Urls { get; set; }
    public Int32 ExpiresInSeconds { get; set; }
    public DateTime GeneratedAt { get; set; }
}
```

#### 方式2：业务后端自行生成签名URL

如果不想每次都调用EasyIO的批量生成接口，可以在业务后端直接计算签名：

```csharp
/// <summary>业务后端直接生成签名URL（无需调用EasyIO）</summary>
public class SignedUrlGenerator
{
    private readonly String _easyIOBaseUrl;
    private readonly String _apiSecret;
    private readonly String _projectCode;

    public SignedUrlGenerator(IConfiguration configuration)
    {
        _easyIOBaseUrl = configuration["EasyIO:BaseUrl"];
        _apiSecret = configuration["EasyIO:ApiSecret"];
        _projectCode = configuration["EasyIO:ProjectCode"];
    }

    /// <summary>生成单个文件的签名URL</summary>
    /// <param name="fileId">文件ID</param>
    /// <param name="expiresInSeconds">有效期（秒），默认3600</param>
    /// <param name="inline">是否内联显示（true=预览，false=下载）</param>
    public String GenerateSignedUrl(Int64 fileId, Int32 expiresInSeconds = 3600, Boolean inline = true)
    {
        var expires = DateTimeOffset.UtcNow.ToUnixTimeSeconds() + expiresInSeconds;
        
        // 签名数据：{fileId}:{projectCode}:{expires}
        var data = $"{fileId}:{_projectCode}:{expires}";
        
        // 计算 HMAC-SHA256 签名
        using var hmac = new System.Security.Cryptography.HMACSHA256(Encoding.UTF8.GetBytes(_apiSecret));
        var hashBytes = hmac.ComputeHash(Encoding.UTF8.GetBytes(data));
        var signature = BitConverter.ToString(hashBytes).Replace("-", "").ToLower();
        
        // 构造URL
        return $"{_easyIOBaseUrl}/signed/{fileId}?expires={expires}&sign={signature}&inline={inline}";
    }

    /// <summary>批量生成签名URL</summary>
    public Dictionary<Int64, String> GenerateSignedUrls(List<Int64> fileIds, Int32 expiresInSeconds = 3600)
    {
        var result = new Dictionary<Int64, String>();
        
        foreach (var fileId in fileIds)
        {
            result[fileId] = GenerateSignedUrl(fileId, expiresInSeconds);
        }
        
        return result;
    }
}
```

[ApiController]

        {
            f.Id,
            f.FileName,
            f.FileSize,
            f.FileId,
            f.Category,
            f.CreateTime,
            // 添加签名URL
            PreviewUrl = signedUrls.FirstOrDefault(u => u.FileId == f.FileId)?.Url,
            ExpiresAt = signedUrls.FirstOrDefault(u => u.FileId == f.FileId)?.ExpiresAt

        {
            FileId = fileId,
            Url = signedUrl,
            ExpiresAt = DateTime.UtcNow.AddSeconds(expiresInSeconds),
            ExpiresInSeconds = expiresInSeconds
        });
    }

## 5. 前端实现

### 5.1 TypeScript 工具类

```typescript
// src/utils/signedUrl.ts

/**
 * 签名URL管理器
 * 功能：缓存签名URL，自动刷新即将过期的URL
 */
export class SignedUrlManager {
  private cache = new Map<number, SignedUrlCache>();
  private apiBaseUrl: string;
  private refreshThreshold = 300; // 提前5分钟刷新

  constructor(apiBaseUrl: string) {
    this.apiBaseUrl = apiBaseUrl;
  }

  /**
   * 获取单个文件的签名URL（带缓存）
   */
  async getSignedUrl(fileId: number, expiresInSeconds = 3600): Promise<string> {
    const cached = this.cache.get(fileId);
    
    // 检查缓存是否有效
    if (cached && !this.isExpiringSoon(cached.expiresAt)) {
      return cached.url;
    }

    // 缓存失效，重新获取
    const response = await fetch(
      `${this.apiBaseUrl}/api/project/files/${fileId}/signed-url?expiresInSeconds=${expiresInSeconds}`,
      {
        headers: {
          'Authorization': `Bearer ${this.getAuthToken()}`
        }
      }
    );

    if (!response.ok) {
      throw new Error(`获取签名URL失败: ${response.statusText}`);
    }

    const data = await response.json();
    
    // 更新缓存
    this.cache.set(fileId, {
      url: data.url,
      expiresAt: new Date(data.expiresAt)
    });

    return data.url;
  }

  /**
   * 批量获取签名URL
   */
  async getSignedUrls(fileIds: number[], expiresInSeconds = 3600): Promise<Map<number, string>> {
    // 过滤出需要刷新的文件ID
    const needRefresh = fileIds.filter(id => {
      const cached = this.cache.get(id);
      return !cached || this.isExpiringSoon(cached.expiresAt);
    });

    // 如果所有URL都在缓存中且未过期，直接返回
    if (needRefresh.length === 0) {
      const result = new Map<number, string>();
      fileIds.forEach(id => {
        const cached = this.cache.get(id);
        if (cached) result.set(id, cached.url);
      });
      return result;
    }

    // 批量获取新的签名URL
    const response = await fetch(
      `${this.apiBaseUrl}/api/project/files/signed-urls`,
      {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'Authorization': `Bearer ${this.getAuthToken()}`
        },
        body: JSON.stringify({ fileIds: needRefresh, expiresInSeconds })
      }
    );

    if (!response.ok) {
      throw new Error(`批量获取签名URL失败: ${response.statusText}`);
    }

    const data = await response.json();
    
    // 更新缓存
    const result = new Map<number, string>();
    data.forEach((item: SignedUrlResult) => {
      this.cache.set(item.fileId, {
        url: item.url,
        expiresAt: new Date(item.expiresAt)
      });
      result.set(item.fileId, item.url);
    });

    // 添加已缓存的URL
    fileIds.forEach(id => {
      if (!result.has(id)) {
        const cached = this.cache.get(id);
        if (cached) result.set(id, cached.url);
      }
    });

    return result;
  }

  /**
   * 清除缓存
   */
  clearCache(fileId?: number) {
    if (fileId) {
      this.cache.delete(fileId);
    } else {
      this.cache.clear();
    }
  }

  /**
   * 检查URL是否即将过期
   */
  private isExpiringSoon(expiresAt: Date): boolean {
    const now = new Date();
    const diffSeconds = (expiresAt.getTime() - now.getTime()) / 1000;
    return diffSeconds <= this.refreshThreshold;
  }

  /**
   * 获取认证令牌
   */
  private getAuthToken(): string {
    // 从localStorage或其他地方获取
    return localStorage.getItem('authToken') || '';
  }
}

interface SignedUrlCache {
  url: string;
  expiresAt: Date;
}

interface SignedUrlResult {
  fileId: number;
  fileName: string;
  url: string;
  expiresAt: string;
}

// 创建全局实例
export const signedUrlManager = new SignedUrlManager(
  import.meta.env.VITE_API_BASE_URL
);
```

public async Task<IActionResult> GetProjectAttachments(Int64 projectId)
{
    var userId = User.Identity?.Name;

        return Forbid();

    var attachments = await _dbContext.ProjectAttachments
        .Where(a => a.ProjectId == projectId)

    var signedUrlsResponse = await _fileService.GenerateSignedUrlsAsync(fileIds, expiresInSeconds: 3600);
    var signedUrlDict = signedUrlsResponse.ToDictionary(s => s.FileId, s => s.Url);

    // 3. 组装返回数据
    var result = attachments.Select(a => new
    {
        a.Id,
        a.FileId,
        a.FileName,
        a.FileSize,
        a.FileType,

    }).ToList();

    var userId = User.Identity?.Name;
    
    // 1. 查询附件
    var attachment = await _dbContext.ProjectAttachments.FindAsync(attachmentId);

## 7. 安全建议

### 7.1 后端安全措施

| 措施 | 说明 | 实现方式 |
|------|------|---------|
| **权限验证** | 生成签名URL前必须验证用户权限 | 在业务控制器中检查用户是否有文件访问权限 |
| **有效期控制** | 设置合理的过期时间 | 图片/文档：1-4小时，视频：2-24小时，临时分享：5-30分钟 |
| **最大有效期限制** | 防止生成超长期URL | EasyIO限制最大7天，业务层可进一步限制 |
| **签名算法一致** | 使用统一的签名算法 | 复用 ApiSignatureValidator.ComputeSignature |
| **密钥安全** | ApiSecret妥善保管 | 存储在配置文件，不写入代码，生产环境使用环境变量 |
| **访问日志** | 记录所有文件访问 | EasyIO自动记录访问日志（IP、时间、文件ID、访问类型） |

### 7.2 前端安全措施

| 措施 | 说明 | 实现方式 |
|------|------|---------|
| **不在前端计算签名** | 签名计算必须在后端进行 | 前端只负责调用业务API获取签名URL |
| **不缓存签名URL到localStorage** | 避免泄露 | 使用内存缓存（Map），页面刷新后重新获取 |
| **HTTPS传输** | 防止中间人攻击 | 生产环境必须使用HTTPS |
| **及时刷新过期URL** | 避免使用过期的签名 | 提前5-10分钟刷新即将过期的URL |

### 7.3 EasyIO层安全保障

- **签名验证**：每次访问都验证签名有效性
- **时间戳检查**：验证 expires 参数，拒绝过期请求
- **项目隔离**：签名绑定项目ID，无法跨项目访问
- **限流保护**：IP和文件级别的访问频率限制
- **防篡改**：任何URL参数被修改后签名验证失败

## 8. 性能优化

### 8.1 批量生成签名URL

**问题**：逐个生成签名URL会产生大量HTTP请求。

**解决方案**：使用批量生成API

```typescript
// ❌ 不推荐：逐个生成
for (const fileId of fileIds) {
  const url = await getSignedUrl(fileId);
  urls.push(url);
}

// ✅ 推荐：批量生成（1次请求）
const urls = await getSignedUrls(fileIds);
```

### 8.2 缓存签名URL

**策略**：在前端内存中缓存签名URL，避免重复请求。

```typescript
// SignedUrlManager 内置缓存机制
const url1 = await signedUrlManager.getSignedUrl(12345); // 请求后端
const url2 = await signedUrlManager.getSignedUrl(12345); // 使用缓存，不请求后端
```

### 8.3 预加载签名URL

**场景**：用户可能查看的文件提前生成签名URL

```typescript
// 页面加载时预生成常用文件的签名URL
onMounted(async () => {
  const commonFileIds = [101, 102, 103]; // 项目logo、背景图等
  await signedUrlManager.getSignedUrls(commonFileIds);
  
  // 后续使用时直接从缓存获取，无需等待
});
```

### 8.4 CDN加速（可选）

如果EasyIO部署了CDN，签名URL可以利用CDN缓存：

```
原始URL：https://api.example.com/api/v1/io/signed/12345?expires=...&sign=...
CDN URL：https://cdn.example.com/api/v1/io/signed/12345?expires=...&sign=...
```

**注意**：签名URL包含 expires 参数，CDN需要配置忽略该参数进行缓存，否则每个签名URL都会穿透到源站。

## 9. 常见问题

### Q1: 签名URL过期后怎么办？

**A**: 前端应该**提前刷新**即将过期的URL，而不是等到过期后再处理。

```typescript
// 推荐做法：提前5-10分钟刷新
if (expiresAt - now < 10 * 60 * 1000) {
  const newUrl = await signedUrlManager.getSignedUrl(fileId);
  updateImageUrl(newUrl);
}
```

### Q2: 签名URL可以分享给其他人吗？

**A**: 可以，但有风险：
- ✅ **适合短期临时分享**（5-30分钟有效期）
- ⚠️ **不适合长期分享**（任何获得URL的人都能访问，直到过期）
- ❌ **不适合高敏感文件**（应该使用专门的分享功能，记录分享日志）

**推荐做法**：实现专门的文件分享功能

```csharp
// 生成分享链接（存入数据库，记录分享人、访问次数）
[HttpPost("share")]
public async Task<IActionResult> CreateShareLink(Int64 fileId, Int32 expiresInMinutes)
{
    var shareToken = Guid.NewGuid().ToString("N");
    
    await _dbContext.FileShares.AddAsync(new FileShare
    {
        FileId = fileId,
        ShareToken = shareToken,
        CreatedBy = User.Identity.Name,
        ExpiresAt = DateTime.UtcNow.AddMinutes(expiresInMinutes),
        AccessCount = 0
    });
    await _dbContext.SaveChangesAsync();
    
    return Ok(new { shareUrl = $"https://example.com/share/{shareToken}" });
}

// 通过分享链接访问（记录访问日志）
[HttpGet("share/{shareToken}")]
public async Task<IActionResult> AccessSharedFile(String shareToken)
{
    var share = await _dbContext.FileShares.FirstOrDefaultAsync(s => s.ShareToken == shareToken);
    
    if (share == null || share.ExpiresAt < DateTime.UtcNow)
        return NotFound("分享链接不存在或已过期");
    
    // 记录访问
    share.AccessCount++;
    await _dbContext.SaveChangesAsync();
    
    // 生成临时签名URL（30分钟）
    var signedUrl = _signedUrlGenerator.GenerateSignedUrl(share.FileId, 1800);
    
    return Redirect(signedUrl);
}
```

### Q3: 为什么不直接使用普通的API Key认证？

**A**: 签名URL的优势：
- ✅ **前端友好**：可以直接用于 `<img>`、`<video>` 等标签，无需额外请求头
- ✅ **浏览器缓存**：浏览器可以正常缓存图片/视频，提升性能
- ✅ **并行加载**：浏览器可以并行加载多个资源，无需排队认证
- ✅ **CDN兼容**：签名URL可以通过CDN加速

普通API Key认证需要在请求头传递认证信息，无法用于HTML标签，必须通过JavaScript fetch后转换为Blob URL，性能较差。

### Q4: 签名URL会被搜索引擎收录吗？

**A**: 不会，原因：
- 签名URL包含时效性参数（expires）和签名（sign）
- 搜索引擎爬取时，URL很可能已经过期
- 即使收录，后续访问也会因签名过期而失败

如果希望文件被搜索引擎收录，应该使用 AccessLevel=1（公开），不使用签名URL。

### Q5: 如何实现"仅项目成员可访问"的图片列表？

**A**: 完整流程：

```
1. 用户登录业务系统
2. 用户访问项目页面
3. 业务后端验证用户是否是项目成员
4. 验证通过 → 业务后端批量生成签名URL（调用EasyIO API）
5. 返回文件列表+签名URL给前端
6. 前端直接使用签名URL渲染图片
7. EasyIO验证签名有效性，返回图片内容
```

**关键点**：
- 业务层负责验证"用户是否是项目成员"
- EasyIO层负责验证"签名是否有效"
- 前端无需关心认证细节，只管用URL

### Q6: 签名URL支持Range请求吗（视频拖动）？

**A**: 支持。EasyIO的签名URL访问端点完全支持HTTP Range请求，可以实现：
- 视频拖动播放
- 大文件断点续传
- 音频快进/快退

浏览器的 `<video>` 标签会自动发送Range请求，无需特殊处理。
